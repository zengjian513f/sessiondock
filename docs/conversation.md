# 会话草稿与 SEND

问题报告和普通会话共用服务端 conversation 服务。每个逻辑会话只有一个编辑草稿，保存文本、引用、附件元数据和提交 ID；修订号通过 CAS 防止页面互相覆盖。草稿位于私有 state/conversations 目录，原生 UID、经验证的启动记录和恢复实例关联到同一身份，不按目录或时间猜测、不拼接不同会话。

SDK 可用的 AI 来源新建会话默认进入 SDK，不启动 PTY；Codex 首条消息前不生成原生历史，其他来源的原生落盘时机由各自协议决定，见[多来源 SDK](native-sdk.md)。SDK 未启用的来源默认进入对话页，ptyhost 在后端启动，用户可切换终端。SSH/shell 没有对话归档：PTY 在输入框上方，输入框只有文字和发送（没有附件按钮和 Esc），控制台是纯终端；从输入框发出的命令同样清空服务端草稿，退出的控制台不会以"草稿保留"行回到侧栏。粘贴/选择附件先保存元数据，随即在后台把字节流式上传到私有暂存区（每个草稿最多两路并发，卡片显示排队/进度，允许取消，失败的卡片保留 File 并提供重试）；512 MiB 限制在选择和上传时都检查；一次粘贴超过 5 个文件或合计超过 50 MB 时（输入框、报告表单和控制台一致）先弹确认，取消则不暂存。发布到会话 cwd 的 sessiondock_attachments 仍等到发送：SEND 先等待进行中的上传，只对失败的附件重新上传，再通过检查过的文件写入边界发布。报告的目标 cwd 是仓库。已暂存的引用可跨刷新和跨设备发送；上传未完成时，服务端保留已确认分块，剩余字节仍依赖本页 File，离开页面会提示；刷新或关闭后未完成的附件仍需重新选择。从服务端读到草稿的页面只有附件元数据，没有 File：图片卡片按需从暂存区读回字节显示预览，读不到（已发布、已回收）或超过 32 MiB 时显示类型图标，不留破图。移除附件先保存去掉引用的草稿，再尽力丢弃暂存字节；服务端拒绝丢弃仍被草稿或未完成发送引用、或已发布的上传。

DELTA（SDK 输入）：SDK 和旧对话视图共用同一个服务端草稿及附件暂存机制；空 SDK 创建回执提供可信 uid/cwd，草稿操作不生成原生历史。SDK 发送只引用本会话已上传附件，成功时发布到工作目录；五种 SDK 均将发布后的普通附件路径及引用通过文本交给原生接口，不追加原生图片块；见[多来源 SDK](native-sdk.md)。发送失败保留输入，成功后只清本次内容，发送期间的新编辑保留。SDK 的发送、追加、审批和停止走原生协议，不读取或粘贴 PTY；下述屏幕分类、终端输入租约和 CLI 发送账本契约用于旧对话模式，SDK 协议边界见 [SDK 模式](codex-sdk.md)。

CLI 忙碌时直接 SEND，由 CLI 管理后续消息。选择题、trust、更新菜单或审批阻止发送，前端禁用发送，服务端独立检查并报错，保留输入；回答走终端键盘路径。菜单识别与按键适配见[对话输入就绪](composer-input.md)。SEND 成功清除提交时的草稿修订，不等待 JSONL 确认，不产生暂存消息 stack。发送期间的新编辑保留。稳定提交 ID 防止响应丢失后重复粘贴；已开始写入但结果不明的请求拒绝自动重发。

打开或切换会话只读取草稿，不触发保存。多设备同步的模型是"正在编辑的设备赢，空闲设备跟随"：输入框在首次读取返回前禁用；从未保存过的页面在首次读取时采纳服务端修订号（若仍有读取前进入的本地内容，排在服务端内容之后并入并保存），不会因修订号停在 0 而被反复拒绝；保存遇到 `draft_revision` 时重读一次服务端草稿、换成其修订号后重发（最多两次），只有仍失败才显示错误。空闲页面（没有未保存编辑、没有排队保存）在收到 `/api/events` 的 `drafts` 通知时立即重读草稿，另外通过 `check` 轮询带回的 `draft_revision`、切回会话、页面重新可见和窗口聚焦跟随更新，采纳时保留本页仍持有的附件 File、预览和进行中的上传。不做字段级合并。页面按稳定提交 ID 查询服务端发送结果，包括后台发送的报告首条任务；查询期间的新编辑及未上传 File 保留。服务端在完成发送、保存和启动恢复时，用提交 ID 与回执摘要核验待发送副本，仅清除已发送的文字、附件和引用，阻止旧页面将其写回；后续新增内容保留，不建立已发送正文归档。

报告使用临时草稿身份，提交后绑定到普通处理会话的同一个草稿。诊断包按报告请求 ID 冻结一次，第一条任务经共用 SEND 交给普通配置的 CLI；诊断文字仍是数据。启动/发送失败保留草稿，退出且未绑定的 CLI 可重新启动（新建空会话也显示“重新启动”，无需先填写草稿），报告的实例关联和提交状态同步更新。附件移除或取消一键完成；上传成功发布后删除私有字节副本，无引用的暂存与中断残件超过 24 小时回收，保留历史文件与不确定写入所引用的附件。

草稿修订号只在各自的服务端草稿内递增。Codex 原生记录轮换后，经验证的终端重绑定可携带页面输入进入新草稿；保存冲突时必须采用对当前目标重新读取的修订号，包括比旧草稿更小的值或 0，保留输入并按原 CAS 规则重试，不能把跨草稿修订号当成全局递增序列（BUG-20261013-072020-c43ef6）。

旧客户端记录按可验证 UID 导入；旧 File 原件先复制到私有服务端，再删除已验证的浏览器副本。成功消息归档不恢复到草稿，多个旧副本不合并。无法确认身份的数据及未迁移 File 保留原件。旧服务端账本保留，停止后台派发，新 outbox 投影返回空列表及只读 legacy_delivery。

SEND 和 `check` 使用同一 PTY 编辑区分类器，返回 `ready / starting / blocked / unknown` 及原因，前端直接用于按钮和提示。原生历史/hook 问题保留问答展示，不再独立否决 SEND；身份、草稿和去重检查仍独立。识别、短暂等待和兼容边界见[对话输入就绪](composer-input.md)。

会话页的 CHECK、SEND 和回答不依赖浏览器 PTY 控制权，也不抢占已打开的终端。服务端仍核验完整会话与实例身份，并在每次 host 操作时串行写入。只有用户主动进入 PTY 模式且终端由其他页面持有时，才询问是否接管。

Claude 原生 `continued-in` 续接后，CHECK/SEND 与控制台沿目录中的 `continued_in` 关系查找原会话的唯一运行中受管实例（沿用控制台的八跳范围）。每次操作保留原 host 的 SID、UID 和实例 guard，不重写绑定；没有明确续接关系的同目录会话不继承终端。[续接浏览器套件](../tests/claude_continuation_browser.py)覆盖节点与 Hub、宽窄屏和明暗主题下的草稿保留、发送、原生单次落盘、同一终端及刷新后再次发送。

## HTTP

对话与问题报告共用通用“文件”入口，没有单独的 PDF 入口或文件扩展名白名单。
Android 上优先使用可用的 `showOpenFilePicker`，允许多选和所有类型；取消不上传、不再打开另一个选择器。
API 不可用或不受当前页面支持时，回退到 `accept="application/octet-stream"` 的文件输入。
Android Chromium 将这个通用类型作为所有可打开文件处理，同时不加入空 `accept` / `*/*` 引出的相机、录像和录音来源。
其他平台的文件输入保持不限制类型；图片、视频、音频入口保留各自的类型提示。
所选文件仍经同一暂存、草稿恢复与 SEND 路径；系统选择器的界面由设备与浏览器提供。

| 接口 | 行为 |
| --- | --- |
| GET/POST /api/session/conversation | 读取草稿 / `{uid, revision, value}` CAS 保存；任何草稿修订号变化（保存、发送清空、导入、启动修复）都在 `/api/events` 发布 `{drafts:true}` |
| GET 同接口带 request_id / report_request_id / legacy=true | 查询 SEND / 报告结果 / 只读迁移证据 |
| POST /api/session/conversation/attachment | `{uid, id, name}` 查询参数，原始流式文件体；可同时带 `offset,total` 续传分块；完成返回 upload_id，否则返回已确认 offset |
| GET /api/session/conversation/attachment/status | `{uid, id}` 查询已确认 offset、total；已完成时带 upload_id；尚未开始返回 offset=0 |
| GET /api/session/conversation/attachment | `{uid, id}` 读回暂存字节；图片类型原样下发，其余按不透明字节，一律 `nosniff` 加沙箱 CSP；已发布或已回收的上传返回 404 |
| POST /api/session/conversation/attachment/discard | `{uid, id}` 丢弃未发布且无引用的暂存上传；返回 `removed`，被引用或已发布返回 409 |
| POST /api/session/conversation/check | 检查 PTY 输入状态；画面检查结果带 `input`、`draft_revision` 和会话 [CLI 状态对象](cli-state.md) `cli`，供前端展示及空闲草稿同步 |
| POST /api/session/conversation/queued/dismiss | `{uid, request_id}` 关闭一条排队中/未送达的发送记录；不重发 |
| POST /api/session/conversation/send | `{uid, request_id, text, attachments, quotes, draft_revision, lease}` |
| POST /api/session/conversation/restart | 已退出、未绑定的实例重新启动，保留逻辑草稿 |
| POST /api/session/conversation/import | 只读迁移旧版输入证据 |
| GET /api/session/conversation/drafts | 发现保留输入的会话，包括退出实例；`term/discard` 删除的回执随之清除草稿，不再列出。原生 UID 别名只有在目录里仍有该会话时才挡住草稿清理；已进回收站的会话不算共享。缺少 `session.started` 的旧草稿按账本记录的创建时间回填，侧栏行不随渲染时钟移动 |

状态：sent 表示 SEND 已成功；cli_question 拒绝选择题期间发送；draft_revision 表示编辑冲突；send_result_unknown 不授权重发。需要 state、terminal、runtime、lifecycle、files_write 服务，conversation_send 能力明确启用。测试使用私有目录和假 CLI。

Hub 的启动草稿发现按节点独立记忆结果：成功节点在本页只读一次，不因其他节点失败重复查询。失败节点按 30、60、120、240、300 秒退避，单次请求 12 秒超时；已知离线节点跳过，重新观测到在线时立即恢复尝试。每个节点只允许一条发现请求在途，新加入的节点独立发现。成功返回的草稿立即合入，不等待其他节点；没有新增草稿时不刷新侧栏。当前会话的草稿修订同步与保存队列不受此启动发现缓存影响。

草稿首次读取失败和保存失败会在网络可用时自动重试；读取与保存都有请求期限，避免永久等待。读取恢复后先合并服务端草稿与本页早期输入，再保存，保留附件与引用。失败提示只显示当前错误，不递归叠加；后台恢复仅重试草稿读写，不自动 SEND。

DELTA（弱网恢复）：草稿读写的 12 秒期限覆盖响应体，已有提交 ID 不阻止发送前保存失败后的后台补存。SEND 请求 20 秒无结果后，按原提交 ID 查询回执（查询期限 12 秒）；确认成功才清除对应输入，否则恢复操作并显示行内“结果尚未确认”，保留输入和提交 ID，后续继续核对，不自动再次 SEND。

DELTA（附件续传）：浏览器以 2 MiB 分块上传，发送前查询服务端确认位置；响应丢失时先查进度，只重发未确认部分。服务端完整收到并同步一个请求的字节后才原子更新私有检查点，半截请求不推进位置，下一次续传截掉未确认尾部；检查点可跨服务重启恢复。完成后的发布、去重与权限检查保持原契约。旧节点不支持 status 接口时回退到原完整文件上传。

上传或响应连续 30 秒没有进展时中止本次请求，卡片保留文件和进度提示。连接错误、超时和暂时性服务错误先重试一次；仍失败时按 3、6、12、24、30 秒退避，在页面可见且联网时继续。用户取消后不自动重试，可点击卡片“重试”继续；移除会清理未引用的检查点和部分字节。未完成的残件沿用 24 小时回收规则，不承诺浏览器关闭后保留本地 File。

草稿每次编辑都会立即标记为未保存，保存队列先合并 150ms 内的变更，再异步写入服务端；不是每隔几秒定时备份。刷新只能恢复服务端已确认的内容，尚在合并窗口、请求中或断网期间的输入没有固定的丢失字数上限；这些状态及未上传的附件会触发离页提醒。浏览器强制关闭或忽略提醒仍可能丢失未保存内容。

版本更新提示只阻止 SEND，草稿继续编辑、保存和失败重试。提示中的“重新加载”先等待各会话及报告草稿写入完成；保存失败、新编辑尚未保存、发送尚未结束或附件字节尚未上传时取消刷新，保留当前页面。该保护不代替浏览器自身刷新时的离页提醒。

发送关键路径只等待包含提交 ID 的草稿保存和 SEND，不再串行追加独立 CHECK 或提前重复保存；SEND 仍在发布附件、粘贴和 Enter 前核验画面。成功响应已持久化发送结果并消费对应草稿修订，页面立即清除已发送内容、恢复编辑和发送；剩余内容和后续编辑继续由原有草稿队列后台保存，失败提示和离页保护仍生效。

SEND 成功后清除已发送草稿，并把正文压入会话的 [CLI 状态对象](cli-state.md) `queued`；页面在对话末尾（活动状态行之后）按用户气泡显示它，标注"已发送，等待 CLI 处理"，原生历史出现 CLI 入队记录或服务端读到 Codex 终端队列中的匹配正文后改为"已进入 CLI 队列，当前步骤结束后处理"；发送按钮不转圈、可继续发送。CLI 忙碌或 API 重试时会把输入留在自己的队列里，这一气泡就是该队列在页面上的样子（BUG-20260928-113817-9301c2）。服务端读到对应的原生 user/command 记录后从对象里退掉它，页面随数据包撤掉气泡；不弹成功 toast。排队记录在服务端账本，刷新、换页面、换设备都能看到，不参与回合封装、工具分组、时间分隔和搜索计数。等待期间仍可编辑和继续发送，多条输入按发送顺序对账；Codex 用换行合并为一条完整原生 user 回显时，一并结清对应的连续发送项。回执里的 `echo_hash` 是实际发送正文（去首尾空白）的 SHA-256 摘要；对账以摘要和发送时间边界匹配，已有同文消息、助手输出及重复快照不能提前退掉。附件、引用参与完整正文摘要。已验证的临时会话绑定沿用；不自动重发，不用固定超时假定成功。响应丢失仍按原提交 ID 查询，失败提示与输入就绪状态独立保留。

历史打开的回显对账优先使用本会话已持久化的原生队列键或启动绑定；其他会话存在排队记录不会单独触发终端身份解析。未知绑定仅在本批回显可能匹配发送正文及时间边界时沿用完整身份解析，Codex 合并回显的前缀仅用于候选筛选，不能据此结清队列。最终对账仍核验所属会话、完整正文、顺序及已消费回显；SEND 的实时授权检查不变（BUG-20261011-162855-0b94ac）。

Claude 原生 `popAll` / `popOne` 是把待处理输入退回编辑区；对应发送保留为可关闭的“已退回编辑区，未确认处理”，不再声称仍在 CLI 队列。完整证据与旧回执恢复见 [CLI 状态对象](cli-state.md)（BUG-20261014-151630-58b85b，DELTA）。

Claude 的原生回显可将 tab 精确展开为四个空格，原发送正文及摘要仍保留；转换边界、重复输入和旧回执恢复见 [CLI 状态](cli-state.md)。

Codex 已知内置命令通过 TUI 分派，原命令正文没有同文原生回显，因此 SEND 成功后不进入上述等待队列；`sent` 不承诺命令执行成功或模型任务已结束。服务端按完整发送正文识别首行命令及可带参数形式，保留前导空白的普通输入语义；范围和边界见 [Codex 命令回显](codex-commands.md)。

原生会话身份只从同一次已验证视图读取 scope 和 cwd，不为草稿操作序列化历史消息。CHECK/SEND 在未等待会话锁时复用本请求刚解析的目标；排队等待后重新解析。目标不跨请求缓存，每次捕获和写入仍由 host 核验完整实例身份。目标解析中的 host 观察和 Codex 进程扫描并行执行，仍使用新鲜观察并保留重名拒绝、线程切换及 fork 选择规则。


## 路径补全

DELTA：普通对话与 SDK 输入框共用 Tab 路径补全，不局限于 `!` 模式。
按光标所在词查询文件和目录；相对路径及裸文件名前缀以当前会话 cwd 为基准，
支持绝对路径、`~/`、`./`、`../`、中文、引号与反斜杠转义的空格。
只读取一层目录，跟随目录符号链接，保留输入的路径写法；隐藏文件只在输入 `.` 前缀时参与匹配。
不执行 shell 展开、命令替换或命令，也不修改文件、原生会话或终端。

唯一候选直接填入；多候选复用输入历史列表样式，Tab/Shift+Tab 和上下键选择，
Enter 或点击填入，Esc 关闭。目录追加 `/`（Windows 原生反斜杠写法保留），
可再次 Tab 查询下一层；带空格的路径自动引用。只替换当前词，保留前后文字；
填入经过原有输入事件、草稿 CAS 保存与 SEND 链路。无匹配、读取失败或超时在候选框内说明，
不清空输入。两个输入框中的 Tab/Shift+Tab 都不再切换控件；空输入、选中文字或补全能力不可用时仍保留焦点。
候选框打开后，继续输入、删除或粘贴会保留框并合并 100ms 内的编辑后刷新候选，
输入法组合期间暂停查询，组合完成后刷新。刷新得到唯一候选也不自动改写正在输入的文字，
须按 Tab、Enter 或点击填入；仅首次主动 Tab 的唯一候选直接补齐。
Esc、失焦、移动光标、切换会话或当前词不再有效时关闭候选；异步回复还需匹配原会话、输入文字与光标位置。

`conversation_path_completion` 能力启用时使用
`GET /api/session/conversation/complete-path?uid=…&path=…`，返回
`entries: [{path, directory}]`，禁止缓存。节点从会话身份（含未落盘启动回执）取得 cwd，
Hub 按限定 UID 路由到所属节点；旧节点未声明能力时不查询，Tab 仍保留输入框焦点。
与新建会话目录补全一致，读取遵循服务运行用户的 OS 权限，不以文件预览授权范围限制候选。
没有工作目录的相对路径及实际文件系统错误明确返回失败。
