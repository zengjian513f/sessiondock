# 已废弃：冻结库存（全量启动解析）

**状态：2026-09-12 废弃，被 [read-model.md](../read-model.md) 取代。**
本文只记录这套设计是什么、为什么废弃，供阅读第 1–33 批账本时对照；
任何新代码、新文档都不得再以它为依据。

## 它是什么

第二批起，`SessionStore` 在每次刷新时对三个读根做一次"冻结库存"：

- 枚举全部候选文件，对**每一个**文件全量读取并解析（LF 检查点、前缀
  digest、provider 投影），把投影出的全部消息对象常驻内存（`Parsed.events`）。
- 解析完成后再枚举一次，只要有任何文件的 stamp 与解析时不同，就拒绝发布这
  一轮（`503 会话文件正在变化，请重试；上一份完整索引未被覆盖`）。
- 列表行、fork/子代理归属图、搜索、`/api/live` 原生目录、回收站文件集都从这
  份快照上取。
- 预算写死：最多 1000 个会话、总计 256 MiB、进程内 32 MiB 索引容量、
  16 个视图 / 16 MiB 序列化消息。

设计动机是"一致性"：同一时刻的一张全局快照，让签名、归属、游标互相可证。

## 为什么废弃

2026-09-12 首次接真实读根（772 个会话，3.4 GB）的实测：

| 现象 | 数字 |
| --- | ---: |
| 直接列表 | 413 `M1 最多索引 1000 个会话` |
| 放宽预算后冷启动全量解析（单线程） | 23 s |
| 解析期间有活跃 CLI 追加 → 拒绝发布 | 每次 |
| 常驻内存 | O(总字节)，估计数 GB |
| 对照：Python 头 96 KiB + 尾 512 KiB 列表 | 冷 1.2 s / 热 0.7 s |
| 对照：读 3.4 GB 全文（页缓存热） | 0.38 s |
| 对照：读 761 个文件的头尾共 249 MB | 0.04 s |

结论（用户 2026-09-12 17:52）："超过 10 秒就是错误的设计，应该推翻重来"。
多线程能把 23 s 压到 2–3 s，但改不了常驻内存和"整份作废"两条；全局一致性
在本机单用户场景没有任何消费者真正需要。

## 与新设计的对应

| 旧 | 新 |
| --- | --- |
| 启动全量解析 | 无启动解析；列表 = stat + 头/尾摘要 |
| `Parsed.events` 常驻全部会话 | 只为打开的会话建视图，LRU 有界 |
| 整份快照一致性、拒绝发布 | 每文件独立；变化只影响自己 |
| 1000 会话 / 256 MiB 上限 | 无上限；单文件 256 MiB 只在打开时生效 |
| 搜索读冻结快照 | 按需流式扫描、`partial` |

保留不变的部分：单文件解析机械（`records/`、`native_input.rs`、
`providers*`、`pages.rs`、`media_projection.rs`）与每会话视图契约。
