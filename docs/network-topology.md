# 运维：两套 WireGuard 不得混用身份

SessionDock 节点通信只走 `10.66.66.0/24`。另一条中继路径上的 `192.168.2.10`
**不是 Cetus**。下文地址由运维明确要求写入本文，不是凭主机号后缀推断出来的。

本文不记录 token、公私钥、凭据、个人绝对路径或防火墙命令。

## 身份规则

- `192.168.2.10` 是**另一套** WireGuard 安排里的中继主机/路径，**不是 Cetus**，
  也永远不得当作 Cetus 的地址使用。
- 该中继路径的网段、接口名与网络名称目前未核验。本文只称它为「单独的中继路径」，
  不臆造其配置。
- 两套网络可能复用相同的主机号后缀（例如都出现 `.10`）。后缀相同**不能**证明
  是同一台机器，也证明不了任何身份。
- Cetus 的 SessionDock 地址只有 `10.66.66.10`。看见 `192.168.2.10` 时按中继路径
  处理，不要当 SessionDock 节点。

## SessionDock mesh

已核验的 SessionDock mesh：接口 `wg0`，子网 `10.66.66.0/24`。

服务路由（经本 mesh，不用单独的中继路径）：

- Hub 访问各节点第二监听：TCP `8743`。形状见 [deploy-hub.md](deploy-hub.md) 与
  [security-model.md](security-model.md#node-listener-hub-traffic)。
- Cetus 管理 SSH：`10.66.66.10` 端口 `22`。
- Orion 仍是遗留 Python 节点，可能离线。

本机（Lyra）观察到的事实（运维明确要求记录的操作地址）：

- `wg0` 地址：`10.66.66.2/24`
- 对端 endpoint：国内中央中继 `120.76.140.254:51820`
- allowed：SessionDock mesh `10.66.66.0/24`

## 路由核对清单

联系 Cetus 或任何 SessionDock 节点前：

1. 检查 `ip route get 10.66.66.10`，确认走 `wg0` / `10.66.66.0/24`，而不是单独的中继路径。
2. 使用 `10.66.66.*` 字面地址；**禁止**因后缀相同把 `192.168.2.10` 替换成 Cetus。
3. Hub→节点用 `http://10.66.66.<主机号>:8743`；Cetus SSH 用 `10.66.66.10:22`。
4. 若 `ip route get` 未指向 `10.66.66.0/24`，先修 SessionDock mesh，不要改用
   `192.168.2.10`。
