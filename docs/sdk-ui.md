# SDK 与对话状态栏

五种 agent 共用状态栏的布局、可读标签和交互条件。协议能力、计量单位与原生
身份仍以各来源合同为准；一致性不意味着制造缺失数据或不支持的控件。

## 公共接口与适配边界

[ConversationUI](../web/conversation-ui.js) 供 SDK 和普通会话共用：输入框自动高度、
Enter/Shift+Enter/输入法/移动端提交规则、排队用户气泡、状态摘要与详情、菜单定位
及工具控件状态。调用者保留自己的草稿身份、投递证据和操作处理器，公共呈现层不发送请求。
输入框最大高度仍由所在页面决定，不借统一组件改变普通会话的布局。

[SdkUI](../web/sdk-ui.js) 为五种 SDK 提供页面骨架、编辑器绑定、HTTP 错误处理、
历史窗口读取、历史过程折叠恢复、底栏空间分配和菜单生命周期。视图通过
`uid/agent/generation/pane` 标识自身，提供 `send/interrupt/paintHistory/paintStatus/layoutToolbar`
及设置回调；原生快照、消息身份、消费确认、审批回答和会话动作仍由适配器处理。
不再从 Codex 视图借用通用方法。

五种 SDK 的草稿、附件、引用和路径补全继续共用
[composer](../web/codex-sdk-compose.js) 与普通会话的草稿存储；历史继续使用普通
会话的缓存、分页及 `planTurns/buildPlan/msgNode` 渲染器。公共 HTTP 方法只负责
传输错误，不替代普通会话的投递账本，也不合并不同来源的原生 API。

DELTA：五种 SDK 点击发送后保留编辑器焦点；排队正文与普通用户消息共用 Markdown
渲染，状态及动作保留在正文下方。四种原生 SDK 刷新历史时也按 turn 身份保留已展开
的过程，菜单关闭、窗口变化和键盘详情沿用共同生命周期。消费确认不由气泡外观推断。
完整审阅范围和保留差异见[五来源对照](sdk-feature-audit.md#交互与呈现审阅)。

## 查看、启动与停止

DELTA（BUG-20261019-160908-75ee7f）：Codex、Claude、Grok、Agy、OpenCode
的 SDK 视图将查看历史与启动分开。未运行时选择会话、切换到 SDK 或刷新页面
只读历史，不调用原生 `/open`、模型目录或实时用量接口；不显示输入框及底栏，
不点亮活跃标记，不改变会话更新时间或列表排序。已有运行实例可重新连接。
连接已有 Codex 实例产生的设置／用量记录也不算新对话活动；排序依据与回归见
[读模型的 Codex 活动时间](read-model.md)。
刷新时若运行状态晚于历史到达，当前 SDK 视图随 SDK 活跃证据恢复连接与输入栏，
保留历史和草稿；重复状态通知不重复连接，不改变用户已切换的视图。
设置 → 功能为五种 agent 分别保存 SDK／CLI 启动方式（默认 SDK，浏览器偏好）。
浏览器尚未记录该会话视图时，SDK 默认方式进入 SDK 视图，CLI 默认方式进入普通对话；
已记录的会话视图优先，五种来源均保存该偏好。进入视图仍只读，不触发启动。
新建、接续会话、标题栏／右键启动和 Report Bug 共用此设置；右键启动没有二级菜单。
启动自动进入对应 SDK／终端画面，CLI 新建保留普通对话输入入口。
不可用时显示原因，不静默改用另一种方式。更改偏好不停止或转换已有运行实例。
新建 SDK 成功后直接连接已创建的会话并显示输入框；连接期间禁止重复启动，
不必等待下一轮活跃列表刷新。发送首条消息后继续使用同一 UID 与服务端草稿。
Codex 在文件落盘但列表尚未发现它时，以仍在运行的创建回执补齐活跃标记。
CLI 首条原生记录出现后的自动跟随保留对话／终端选择、草稿与输入焦点。
SDK 接续以新 UID 保存前序关系，不依赖页面留在现场等待原生文件出现。
Claude、Grok、Agy 的 SDK 与独立 CLI 不共享运行实例；SDK 运行时终端入口说明
须先停止 SDK，服务端也拒绝接管（包括强制接管），不自动结束 SDK 或另启 CLI。
Codex 与 OpenCode 仍遵守各自的原生共享合同。

“停止会话”阻止待投递输入继续执行并释放所选桥接运行实例，保留原生历史与未发送草稿。
Codex 中断并取消订阅所选线程，保留共享 daemon；Grok、Claude、Agy 结束本桥接
拥有的进程，OpenCode 调用所选会话的原生中断并释放观察，不结束共享服务。
停止事件同步到其他已连接页面，页面回到无底栏的历史视图，重开不会自动启动。
输入框旁的“停止”仍只中断当前回合；切换页面和关闭标签页不等于停止会话。

验收：[五来源启动与停止](../tests/sdk_start_stop_browser.py)覆盖节点与 Hub、
宽窄屏、明暗主题、只读打开／刷新／切视图、更新时间和顺序、双页面停止与再次启动。

## 状态与空间分配

DELTA：SDK 和普通对话底栏始终单行。先保留可读状态摘要，再分配用量空间；
模型、强度、模式、权限和动作放不下时进入 ⋯，仍超宽的用量在自身区域横向滚动。
状态摘要最多六字，完整原因保留。模型框适配目录名称，最多 160px，窄屏继续收缩，长名称可查看全文。

| 颜色 | 状态 | 圆点动画 |
| --- | --- | --- |
| 绿 | 就绪、压缩完成 | 静止 |
| 蓝 | 处理中 | 呼吸 |
| 琥珀 | 待批准、待回答、等待发送、队列暂停 | 重试时呼吸，其余静止 |
| 紫 | 压缩中 | 呼吸 |
| 红 | 请求或原生操作失败 | 静止 |
| 灰 | 连接、重连、普通提示 | 连接、重连时呼吸 |

圆点与文字同色，沿用现有主题；减少动态效果时关闭动画。只有全文包含额外信息
或文字被截断，状态才开放点击、触摸和 Enter 详情。完整短状态不可操作、不进入
键盘焦点；恢复短状态关闭旧详情。错误保留原文，不弹重复状态 toast。
原生回执与完成回复矛盾时，状态显示琥珀色“结果待核对”，详情保留冲突原因；
不以红色执行失败或成功状态替代尚未确认的结果。

## 用量与菜单的显示条件

额度、上下文和已知 Token 留在状态栏，**不因某来源有额度就把整组额度复制到菜单**。
Codex 的重置卡是可兑换动作，仅在原生返回可用卡时出现，不是通用额度明细面板。
普通对话只读额度快照，不为显示用量启动 SDK。

五种 SDK 有真实 Token 明细时，直接在 ⋯ 展示累计 Token、
输入/输出、思考、缓存及可用成本，刷新与标题同行，不再套“用量明细”按钮。
Codex 从原生累计 usage.total 显示输入、输出、缓存读取和思考（计入输出），不推算成本。
无 Token 数据不生成空白 Token 卡片；原生步骤统计单列，不与累计值相加。
额度组不在菜单重复展示；上下文、Token、账号额度的统计范围不得混用。
窗口、已用/剩余、分组、缺失与真实采集时间的含义见[额度合同](quotas.md)。

菜单复用原生 select、名称/值分列和无外框动作行。目录去重，目录查询失败仍可
显示已知原生值；未知值不伪造为“默认”。只显示原生声明的能力；空菜单、空组、
孤立分隔线隐藏。菜单按视口及缩放限位，异步内容改变高度后重新定位。

## 缓存与异步更新

DELTA：重新打开 SDK 时，先同步展示本页该 `(节点、UID、agent)` 的最近用量；
账号额度按节点/来源共享。Codex、Agy、Claude 的冷入口另行读取服务端额度快照，
不等待 SDK `/open`、模型目录、历史或实时流。没有已知值时隐藏缺失项，不伪造零。
服务端额度持久化与刷新有效期见[额度合同](quotas.md)；本页 Token/billing 缓存
不承诺跨浏览器重载或节点重启恢复，也不把缓存当作运行状态、权限或操作授权。

缓存先绘制，实时查询后台更新；刷新中及失败后保留最近成功值。`/status` 立即
展示已有状态，四家原生 SDK 的 `/usage` 立即清除已处理命令并后台刷新，不等待查询
才打开可用菜单。失败保留原文和旧采集时间，不能推算重置后已满额。

独立 usage/billing 读取失败按 1/2/4…30 秒退避，成功恢复初始间隔；关闭视图取消
读取和重试，迟到响应不覆盖其他会话或较新结果。取消读取不取消已接受的原生任务。
模型、强度及其他设置选中后立即请求本来源接口，不积累到发送正文。等待原生确认时
保留所选值与草稿，暂时禁用设置和 SEND；失败回到已确认值。普通发送不携带旧设置覆盖，
运行中变更的原生边界见[多来源 SDK 合同](native-sdk.md)。
运行中普通发送显示“排队”。队列操作期间保持禁用控件，返回后绘制最新快照。
DELTA（BUG-20261020-065559-70fe5d）：四种原生 SDK 的普通输入在准备、排队、
投递阶段直接使用右侧用户气泡，与 Codex 队列一致；状态及可用操作放在气泡下方，
不再先画成左侧“正在提交”请求卡片。OpenCode 原生 inbox 沿用同一用户气泡。
用户气泡表示提交内容，不构成原生消费或完成证据。
原生 SDK 的已接收回执使用右侧轻量状态文字，不再以左侧卡片重复发送正文；
接收不代表处理或完成。失败、结果待核对及可撤销队列仍保留正文与恢复操作。
结果待核对记录按消费证据说明原生是否已读取输入；入口明确写“重新发送”，
表示再次提交整条输入，确认框保留重复执行提示。明确失败仍使用“重试”。
核对历史后可移除待核对记录以解除后续队列阻塞；移除不会停止原生任务。
