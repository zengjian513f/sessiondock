2026-10-12，BUG-20261012-082941-7a829b。用户报告的是两项同时存在的缺陷：
对话被切成上下两个滚动区，下方独立区域又重复显示上方的问题。

## 证据链

完整检查报告的 manifest、browser-state、environment、316 条浏览器审计事件、
terminal 和附件。报告环境为提交 `eec6e961`，工作区干净。以下相关提交均已包含在该版本，
不是修复没有进仓库或生产仍运行修复前的版本。

原生 JSONL 与 hook 文件提供同一个单题 AskUserQuestion，题干、三个选项和说明一致；
生命周期账本记录对应 CLI 仍在运行。当前版本已退役 delivery 账本，报告节点没有该目录。
终端也确实停在同一道问题，长题干物理行前带 `│`。

审计事件 58–70 记录打开会话、读取历史成功和第一次 CHECK 返回 `cli_question`。
随后 SSE 持续正常应用，历史游标不变，没有丢消息或错误地切换原生会话的证据。
第一个数据投影偏差是 Claude 屏幕解析保留了长题干的左边框，导致与 hook 题干匹配失败。
页面因此同时渲染 hook 题卡和 CHECK 题卡。独立 CHECK 容器的 `40vh` 高度与
`overflow: auto` 又挤压对话，产生附件里的第二个滚动区。
报告弹窗打开后的 console button missing 事件来自弹窗遮挡按钮，不是本缺陷根因。

## 本次修复与验收

删除 composer 的独立题卡容器、专属高度/滚动样式及 `renderComposerQuestion`。
`renderConversationQuestion` 统一选择当前 CHECK 菜单或匹配且可回答的完整 hook 问卷，
在对话消息列表里生成一张活动题卡，收起对应未回答历史卡；过期 hook 不再并行生成活动卡。
没有原生历史的启动页面也建立相同的消息滚动区。问卷题干解析去掉每行开头的终端左边框，
其他菜单的命令、路径和范围正文保持原来的解析。

`question_browser.py` 增加长中文题干、逐行边框、三组选项说明、原生 JSONL 与迟到 hook：
在 1723×1039、390×844 和明暗主题下实际滚动历史、填写答案草稿并点击选项，
核对原生答案、单一活动题卡、输入区高度、题卡没有独立滚动和消息草稿保留。
截图分别包含 CHECK 回退卡与 hook 完整卡，由执行者打开观看。
启动信任、四种 CLI 菜单操作与两套历史浏览器回归另外验证各自受影响路径。
全部使用私有临时夹具，不操作生产会话，不运行付费真实 CLI。
