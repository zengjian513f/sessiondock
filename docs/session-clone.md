# 会话整组克隆（设计稿）

状态：**Codex、Claude、Grok 同机新身份克隆及跨节点可选身份复制已接入页面及发布事务；移动、目标前缀合并和完整格式审计仍在实现中**（2026-09-30）。
共同的范围计算、前置检查、锁、传输、验证和页面见 [session-move.md](session-move.md)。
本文规定克隆特有的身份重写和失败处理，不能把普通原生 fork 或文件副本当作完整克隆。
已实现的离线入口、浏览器验证及剩余限制见 [session-transfer-tool.md](session-transfer-tool.md)。

## 行为

- 选择任一会话，克隆其整个连通组，包括所有兄弟分支、祖先、子代理、续接代和物理历史依赖。
- 给组内会话及其附属历史分配新身份，保持组内拓扑、消息内容、分支点、归档和当前版本选择。
- 源组完整保留，新组可独立 resume；原生父子关系只能指向新组，不能继续挂在源组下面。
- 可以克隆到另一节点，也可以克隆到源节点。共享 CLI 存储时只创建一次，新组可能被多节点看到。
- 第一版只支持已停止写入的组。克隆不复制进程、PTY、正在执行的命令或工具句柄。
- 第一版保留与移动相同的 Linux、CLI 根和 cwd 路径范围；不复制 cwd、不创建 Git worktree。
  新旧会话的身份和历史独立，工作目录、外部文件、MCP 服务和工具副作用可能仍然共享。

## 身份映射

在计划阶段生成并持久化一份类型化的映射。键包含来源、身份种类和必要的原生作用域，
不能把全文中所有长得像 UUID 的字符串都当成同一种身份。

| 类型 | 克隆规则 |
|---|---|
| 原生 session/thread ID | 组内每个会话生成新 ID；所有所属记录和父子/fork/续接引用同步更新 |
| Codex rollout ID | 每份物理历史生成新身份；初始 rollout 与 thread ID 相同的关系保持，后续各代仍各有独立 ID |
| 子代理 ID | 按 CLI 的原生格式生成新身份，不假定所有来源都使用 UUID；归属、目录、sidecar 和结构化调用结果同步映射 |
| 消息/事件、turn、工具调用及结果关联 ID | 由来源适配器识别原生作用域；属于克隆记录的身份及配对引用一致重映射，保留顺序和关系 |
| SessionDock uid | 从目标来源和新路径按既有规则计算，不直接随机分配；Hub 再加目标节点命名空间 |
| cwd、文件内容中的普通 UUID、外部项目/账户/资源 ID | 不因形似 UUID 而替换；原生项目关联按已验证的元数据导入规则处理，不克隆账户或项目代码 |
| Claude API `message.id` | 保留服务端返回的 `msg_…` 身份；原生 resume 会将其用于 `diagnostics.previous_message_id`。本地记录的 `uuid` 仍重写 |
| PID、PTY、shell session ID、运行时工具句柄 | 不分配伪造的新句柄，不恢复对应运行状态；历史文本可以保留，但不能据此声明目标端可用 |

每个旧身份在其作用域内只映射一次，映射对新身份是单射。不同原生身份类型之间本来要求相等的
关系仍须保持，例如初始 Codex rollout ID = thread ID。目标的新身份与源身份及已有目标身份
均不得冲突；发布时重新核对，不覆盖未知文件或行。

确认后不得临时更换映射。网络重试、Hub/节点重启或结果不确定时，都以同一操作 journal
恢复同一份新组。用户另行发起一次新的克隆才分配另一套身份。

## 文件和引用重写

先校验源文件快照，再在源端私有 staging 中生成克隆文件；跨节点接收时逐项校验输出的大小及摘要。源组数据只读，不修改其
历史文件、数据库行、SessionDock 元数据或执行归属。同机/共享存储克隆会向共享数据库和索引
新增新组记录，因此验证源组原记录不变，不要求整个数据库文件的字节不变。
不能硬链接到源文件，以免新组续写影响旧组。

1. 枚举完整原生文件集、所有身份和引用，建立来源适配器能解释的清单。
2. 按映射生成新目录和文件名，并修改结构化身份字段、父子关系和文件引用。
3. Claude 的 `subagents`、`tool-results`、`file-history` 和 sidecar 必须一起处理。
   原生生成的附件/结果路径即使嵌入字符串，也要由相应格式解析器定位并指向克隆副本；
   不能对任意用户文本做全局替换，不能让克隆读取结果时偷偷回到源会话目录。
4. Grok 的目录、summary、历史中的会话身份和关联按其实际格式更新。
5. 导入原生元数据和历史投影时同步映射主键、外键、rollout 路径和当前选择，不复制整库，
   不把未重映射的数据库行原样搬入新组。
6. SessionDock 的星标等显示元数据复制到新 uid；组内 `spawned_by`/挂靠映射到新 uid，
   组外纯展示挂靠不继承为新组父关系。草稿、启动回执和运行时绑定不复制。

对于会影响恢复或历史访问、但适配器尚不能解释的身份/路径引用，计划必须列出具体阻碍，
不能发布一份部分重写的克隆。普通用户正文出现旧 ID 并不自动构成阻碍，也不是批量替换许可。
克隆来源信息仅作为操作 journal 的追溯记录，不添加一条把新旧组重新连起来的原生父关系。

## Codex 固定前缀

移动要求逐字节复制；克隆会改变身份和路径，因此必须独立计算输出文件及其依赖边界。
不能因新旧 UUID 恰好等长，就直接沿用旧偏移。

- 以物理 rollout 为节点，先处理被依赖的历史，再处理引用它的历史。多代 rollout 和归档文件
  都进入此图；`history_base.thread_id` 按 rollout 身份解析，不能按当前可见 thread 代替。
- 为每份输出记录旧完整行边界到新完整行边界的映射。每个 `end_byte_offset` 必须从被依赖
  文件的映射取得；偏移指向半行、无法解析或依赖缺失时不发布。
- `history_base` 的目标 ID 映射为对应的新 rollout ID；`forked_from_id`、`parent_thread_id`
  则映射为逻辑身份，不能用同一字符串替换规则混淆这两种关系。
- 保留记录顺序、ordinal 及其含义。按原记录一一重写时，`end_ordinal_exclusive` 必须仍与
  映射后边界匹配；任何插入、删除或重新编号都需要额外适配及验证，不能静默发生。
- 重建输出摘要及依赖索引。manifest 分别保存源摘要、目标摘要、身份映射和边界映射，
  不能把“传输原文件校验通过”当作“重写后历史正确”。
- 克隆必须另行验证 `state`、历史投影及子代理图等该版本实际使用的持久化数据，
  不能直接复用移动实验脚本中的原 ID SQL 导入。

### 新身份隔离实验

`tests/session_clone_codex_real.py` 使用真实 Rust 计划/暂存器和**仅供测试的同 schema SQL
导入器**，在临时 CLI home 验证 Codex 0.159.0、Luna low：父会话、分页 fork、归档兄弟、
revert 的多代 rollout、fork of revert；新 ID 的完整分页内容、原生列表、当前文件指针、
名称/置顶/项目关联，以及新旧两组分别续聊。目标无关会话保持不变，克隆期间源历史保持
原样；每个数据库的事务回滚分别验证。证据输出为 `target/session-clone-codex-report.json`。

实验确认原生数据库与 rollout 必须同步映射 thread、turn、item、路径及字节偏移。
`thread_turns.rollout_end_ordinal` 是结束记录的 ordinal，而 `history_base` 使用排他边界，
不能混用。revert 后投影游标可能仍指向旧 rollout，需要以物理文件、字节边界和 ordinal
共同定位，不能总按当前 rollout 重算，也不能因新旧 UUID 等长而保留旧偏移。

这项实验不覆盖 code-mode 子代理引用、跨版本数据库、同机共享存储发布或跨库崩溃恢复。
原生子代理图和工具执行环境仍待完整适配；生产导入不可直接调用此实验 SQL。

## 发布、失败与重试

发布前，新组不可通过 SessionDock 启动；克隆过程中源组保持临时停写锁。验证通过后持久化
完成状态并释放临时锁，两组都可继续。不对源组设置迁出标记，不执行源端 trash、草稿清理或
启动回执删除。移动用的 `retry-cleanup` 不能接受克隆操作。

- 发布失败：按 journal 撤销本次新建文件和数据库行，恢复本次修改的共享索引；保留目标原有
  会话，源组不受影响。只回滚本次对应的行/记录，不用整库或整份索引覆盖并发无关修改。
  回滚失败时保留记录供继续恢复，不报告成功。
- 完成结果不确定：按固定映射检查目标文件、元数据和验证结果，继续验证或回滚；不重新分配 ID。
- 重复确认/重试：返回同一操作及同一新组。已成功的新组后来产生了新内容时，不能用重试的
  旧快照覆盖或删除它。
- 同机/共享存储：冻结源文件清单，新建克隆文件不得被重新扫描进本次源组；锁和清理都按明确
  的身份/路径集合执行。源组锁到期不能成为删除新组或源组的依据。

## 验收

合成浏览器套件与真实 CLI 隔离实验都要区分移动、克隆，不能用一方结果代替另一方：

- 从父会话、任意兄弟分支、任意子代理发起，得到同一个完整连通组；包含 fork-of-fork、
  多代 rollout、归档依赖、续接链和跨 CLI `spawned_by`。
- 新组身份与旧组分离；内部关系指向映射后的成员，每个逻辑节点只克隆一次，每份物理文件
  只生成一次。消息内容和选定历史在身份归一化后等价，不能只核对消息数量。
- Codex 在跨多层父历史边界分页时内容一致；覆盖重写后行长不同的样本，验证偏移重新计算。
- 原生列表、当前 rollout、名称、归档、置顶、项目关联正确；CLI 能按新 ID 恢复。
- 两组分别继续一轮，原生新增记录的所属身份正确，互不追加到对方文件；子代理关系也分别
  正确。真实 CLI 仍使用规定的低成本模型/强度，并断言实际记录，日常默认配置前后不变。
- Claude 的子代理记录、大输出引用和 file-history 可读取；rewind 验证仅在隔离工作目录进行。
- 动态工具定义、历史句柄和运行时能力分别检查，不以记录存在冒充可执行。
- 同机及共享存储克隆、新身份碰撞、克隆第二份、重复确认、传输中断、重写失败、发布失败、
  元数据事务失败、Hub/节点重启后重试，以及完成后继续再重试，均不破坏原组或已有目标会话。
- 运行中成员、未知必要引用、不支持的来源须在页面给出具体原因，不执行部分克隆。
- 克隆操作结束前源组字节、身份、元数据和归属保持原样；源组不存在迁出/trash/清理记录。
  完成后由用户主动继续源会话产生的新内容，才是正常的源端变化。

完整范围验收通过前不声明 `session_clone` 能力。同节点 Codex 使用独立的
`session_clone_local_codex` 能力，范围见下一节。剩余工作统一记录在 [TODO.md](../TODO.md)。


## 当前接口：同节点 Codex

Linux 节点配置 Codex 历史根与私有状态目录后，声明 `session_clone_local_codex`。
Hub 转发操作到所选会话的源节点，返回的新 uid 带同一节点前缀。页面侧栏和标题菜单的
“移动 / 复制整组…”打开表格面板，顶部选择目标机器与操作。每个逻辑会话一行，显示
名称、工作目录、CLI 来源、关联类型、历史文件数量及大小，同线程的多代 rollout 合并计数。
确认本机复制后打开新会话。工作目录不复制。标题栏入口使用与相邻按钮一致的图标，
移入“更多”菜单时显示完整名称，窄屏不把操作名称排成多行。

跨机器选择显示“生成新 UID”：复制默认开启，移动默认关闭；开关表示整组原生身份及内部
引用是否重建。即使保留原生身份，目标机器的 SessionDock uid 仍带目标节点前缀。同机复制
固定生成新身份。当前跨机复制已支持保留身份；移动仍会显示原因并禁用提交，不会
调用本机克隆接口代替所选操作。执行中及结果不确定时锁定选项，重试沿用同一份计划。
不支持的来源或必要引用在计划阶段报错，不能只克隆组中的 Codex 部分。

- `POST /api/session/clone/plan {uid, new_ids?: boolean}`：`new_ids` 默认 true；false 只用于跨节点复制。扫描活动与归档目录、各代 rollout 和原生代理工具引用，
  固定新身份与原生数据库快照，验证并暂存重写结果。返回 `operation_id`、`phase`、
  `target_uid`、`sessions`、`session_count`、`file_count`、`bytes`、`warnings`。
- `POST /api/session/clone {uid, operation_id}`：核对原组关系、字节和元数据，拒绝运行中组，
  发布新文件及原生行，再验证新组。完成后重复提交返回同一结果，不覆盖已经续聊的新组。
- 错误返回 `{code,error}`。冲突、过期计划、运行中会话、未适配原生记录等为 409；
  文件或数据库操作失败为 500。恢复未完成时保留操作记录并阻止该组启动。

原生导入通过实际 schema 枚举所选线程行，不覆盖整库。同步导入状态、分页历史投影、
子代理关系与动态工具定义。计划同时保留所选线程依赖的 `projects`、`project_roots` 和
`thread_sections` 行；同 home 复用已有的相同记录，不捕获无关项目。发布凭据区分计划行和
实际插入行，失败补偿只撤销本次插入，不删除复用的项目；新插入的共享记录若已被其他线程
引用则保留现场。旧版数据库凭据仍可用于启动恢复。code-mode 只解析已知
原生代理工具的字面量身份参数及对应 JSON 结果，不执行 JavaScript，不替换普通文本。
原生 function-call 工具结果同时支持 JSON 字符串和内容项数组：逐项解析 `input_text`，
保留数组、普通状态文本以及图片/音频等非文本项，只有已知子代理身份字段参与映射。
尚未适配的计算式身份引用、附件、目标和实时记录会阻止发布。

操作记录持久化在服务私有状态目录。每个数据库事务同时写入操作凭据，发布文件保留
同 inode 的隐藏标记。进程重启时只补偿有归属证据且内容未变化的本次新增数据；遇到变化
保留现场。恢复先于读模型初始化，避免页面先读到未恢复的发布。此流程不触发源端 trash。

## 当前跨节点复制

Hub 的 `POST /api/session/transfer/clone {uid, target_node, operation_id}` 使用源节点已确认的
复制计划，持久化目标绑定和执行阶段。浏览器关闭不取消已开始的发布；重试复用同一操作和身份。
Hub journal 位于节点注册文件同级的 `transfers/`，启动后可根据两端持久记录重试未完成操作。

源端先在私有 staging 重写身份和字节边界，再经鉴权节点通道传输 tar；原历史保持不变。
清单是第一个成员，后续成员使用编号，文件的原生相对路径只从经过验证的清单取得。
目标校验根目录、工作目录内容、原生数据库 schema、每个文件的长度和摘要，全部接收后才原子
提交接收记录，随后调用发布事务。tar 不能通过路径穿越、链接成员或未声明文件写出暂存目录。
Hub 按块转发，文件数据不整体装入内存；源码版本不同、外部工具和全部附件格式仍需后续审计。

私有 `manifest/check/reserve/export/receive/status/release` 接口只挂在鉴权节点监听器。
源端导出期间以一小时租约阻止受管启动；已知失败和成功都会释放复制租约。目标已完成但响应丢失时，
重试读取目标结果，不重新发布，也不覆盖目标续写。收到完整副本的节点独立验证和发布，不要求它已有源组。
复制不执行源端 trash。共享存储上的新组可能同时出现在两台机器；两台节点仍有各自的操作记录。

关闭“生成新 UID”时，源端暂存逐字节原样文件，保留原生身份、数据库投影和当前 rollout 指针。
目标不存在的数据按原路径导入；文件、执行位及原生行完全相同的数据可以复用。目标已有不同历史、
原生当前版本或显示设置时返回冲突，当前不会自动覆盖前缀或合并分叉。复用文件记录在操作 journal，
原生凭据只登记本次实际插入的行；补偿不删除复用数据。保留身份复制在共享存储上不会形成独立副本，
仍是同一份历史。选择身份开关后重新生成计划；旧节点若未确认支持保留身份，页面禁止提交。

`session_bundle_browser.py` 覆盖共享存储中的两个节点进程和真正分离的 Linux 临时目录：
从页面选择目标并复制三种来源的复杂分支/子代理、打开新历史、节点/Hub 重启后重试；
另验证错误 cwd、根路径、摘要损坏、截断 tar 和路径穿越不会发布文件。
`--peer <SSH 别名>` 为显式启用的双机模式，只创建临时目录和 loopback 节点，经 SSH 隧道连入测试 Hub。
`--preserve` 覆盖保留 ID、原样字节、相同目标复用和复用后崩溃补偿；双机模式另外验证目标续写后的冲突拒绝。
