# 迁移事务与已有记录恢复

当前用户操作是[选择会话并跨机移动](session-move.md)，原生 ID 固定。复制和生成新身份
已从新计划及页面移除。本文件说明底层发布/补偿合同与已有记录的恢复边界。
历史名称 `clone` 仍出现在 URL、原生数据库回执和结构体中，不授予新建复制的能力。

## 行为

候选关系树和实际迁移集合分开。用户确认源机器、目标机器和选择集合，事务保留原生身份，
只发布所选会话及其实际物理依赖。显示附属关系允许跨机器。
目标历史验证、源归属交接、源端清理、目标激活各阶段持久化；原生读写的授权仍由节点负责。

## 身份映射

新迁移的 session/thread、rollout、turn、record、tool call、goal、附件和原生子代理身份不变。
同线程多代历史和固定前缀仍按具体 rollout 解析，不能以可见行代替物理文件清单。
Hub UID 包含当前位置，旧位置通过持久迁移记录解析；同 SID 的无关节点不自动成为后继。

## 文件和引用重写

新迁移保留原生历史字节和引用。只复制必要原生文件，不插入缺失字段，不重新序列化记录。
旧的已确认改身份事务仍按其持久化映射恢复，不能重分配身份：仅替换已识别的身份、路径及
相应偏移字节，保留其它空白、换行、键顺序、转义、正文和不透明 payload。
不使用全文替换，也不为运行时句柄分配伪造身份。

## Codex 固定前缀

`history_base` 指向物理 rollout 和固定字节/ordinal 边界，依赖必须完整。
新迁移不改原身份，保持原始边界；已有改身份事务从保存的映射恢复边界。
原生 state/history/goals 等数据库仅按所需线程导入，不覆盖整个数据库。

### 原生历史边界

原生 `thread/revert` 等操作可能为同 SID 产生多代 rollout。清单、当前选择、归档、
固定前缀及递归依赖一起固定，执行前核对；不能按“最新文件名”猜当前版本。

## 发布、失败与重试

journal 保存选择、源/目标节点、身份、文件清单、原生行、显示设置和发布阶段。
预览只保存计划，执行阶段才创建私有暂存。重试沿用同一事务；暂存未完成时可重建，
已发布内容按保存的回执补偿，不覆盖未知文件、原生行或并发修改。
原生数据库回执采用流式 JSON 和最多 64 KiB 的 SQLite BLOB 分块，主记录仅保存
版本与块数；块、主记录与导入行在同一事务提交，避免合并凭据超过 SQLite 单值限制。
回滚按序读取分块并保留原有逐行校验，终态清理同时删除主记录和分块；旧整包 JSON
回执仍可恢复，缺失或损坏的块不会按旧格式忽略。

移动目标先围栏；源端交接决定持久化后不能撤回执行归属，只能继续清理/激活。
源端清理只处理本次所选历史，`nest_parent` 不作为必须同机保存的物理引用。
原生文件/数据库、显示设置、原生名称索引各自保留恢复证据。
源历史只有清理进入回收站后才从原位置消失；任务失败和断线不代表可重新执行另一份事务。

终态先持久化，然后清理私有暂存、导出包、回执及冗余原生行快照。精简账本保留身份、
阶段、归属与结果，重启重试返回同一结果，不再搬动历史；精简失败单独记录并可重试。
已有复制或改身份记录仍可读取、查询、取消及按记录恢复，不提供新建复制入口。

## 验收

新选择行为和原生移动由[选择迁移套件](../tests/session_selected_move_browser.py)覆盖。
原生大回执的发布失败、重启回滚和旧回执兼容由
[分块回执套件](../tests/session_receipt_chunks_browser.py)覆盖。
已有事务恢复遵守这里的补偿及持久化规则，不能通过丢弃日志、改操作 ID 或覆盖原生库解除围栏。

## 当前接口：同节点 Codex

历史能力名 `session_clone_local_codex` 继续表示节点具有迁移原生适配器，覆盖 Claude、Codex、Grok。
同节点新建复制已停用。`/api/session/clone` 保留给认证传输层在接收节点发布，以及恢复已有记录；
新计划只接受跨机移动及保留 ID。页面和能力说明见[迁移合同](session-move.md)与
[能力合同](capabilities.md#group-cloning)。

## 当前跨节点复制

不再提供新建跨节点复制。Hub 的 `session_clone_remote` 为 false，旧事务的协议、
身份映射和补偿代码仅用于恢复已持久化任务。旧任务的恢复不改变新迁移的固定身份策略。
